# 摩天楼 Skyscraper · 楼高可见数推理

一个零猜测的益智盘：四条边上印着数字，盘里填楼高。**每一个数字都是从这根箭杆方向望进去能看见几座塔**，
不是提示，不是候选，是题目本身。

本页每一个数字都是本轮（HEAD `1a2f479`、Node `v26.8.1`、macOS、2026-09-28 01:06 CST 一次会话）重跑

## 规则（玩家视角）

- 盘是 `n×n`，**每行每列都是 `1..n` 的一个排列**：`1` 最矮，`n` 最高，同一行同一列不会有两个一样的高度。
- 边上印的数 = 站在这条边上往里看，**能看见几栋楼**。一栋楼看得见，当且仅当它比它前面所有楼都高；
  `n` 楼一旦进入视野，它后面什么都数不进去。
- 于是有两个"一开口就说死"的读数（引擎里就是 `js/engine/skyscraper.js:148` 的 `Rules` 里这两条：`one:` 在 `:149`、
  `all:` 在 `:156`）：
  - 写着 **1**：只看得见一栋 → 撞上的第一眼那格就是 `n` 楼。
  - 写着 **n**：栋栋都要看得见 → 从这一边往里必须一路升高。
- 中间的数靠的是**整行相容排列集**：一条线只有 `n!` 种摆法，先把对不上两端读数的摆法全划掉，
  **剩下的每一种摆法都同意的格子才落得下子**（`surviving()` 与 `Rules.set`，`js/engine/skyscraper.js:540`、`:184`）。
  这也是这一局不需要猜的原因。
- 两端读数是有物理上限的：最高的那栋楼两头都看得见，所以一条线两端的数加起来不能超过 `n+1`；
  写坏了的题目在构造阶段就被拒收（`js/engine/skyscraper.js:99`）。
- 出货的档位只到 **6 阶**。`MAX_N = 8` 是排列表的上限而不是游戏的上限（`js/engine/perm.js:17`）：
  7 阶盘可以合法地交给引擎，但没有任何一档能生成它（原因见下面的实测）。

操作：点击一格轮转 `空→1→…→n→空`；选中键盘上的数后拖动，一笔把同一高度抹过若干格；
候选模式记铅笔（写了数字的格，候选自动清空）。键盘 `1..n` 选高度、`回车`/空格 写入选中格、
方向键移动、`X` 清除、`N` 换候选、`H` 提示、`Z` 撤销、`W` 抹掉候选、`Esc` 回选关。

### 这两套中位数**不可互换**

出厂题池的中位数（`61.9 / 67.8 / 125.0 / 136.7 / 228.5`）和 `balance` 现场抽题的中位数
（`55.6 / 64.8 / 114.4 / 133.4 / 230.3`）**是两个不同总体的读数**，不是同一件事的两种写法：

- 出厂池是**四关**，而且是 `campaign|<tier>|<j>` 这一族种子里"第一批落进带内且线索串不重复"的盘 ——
  带内择优之后的**截断样本**，`n=4`。
- `balance` 是每档**现场生成 24 题**、按 `balance-<tier>-<k>` 取种子，量的就是这个档今天还能不能落进带 ——
  它的作用是让阶梯"断掉"时构建变红，不是给菜单印一个分数。
- 两个方向都会偏：`master` 档现场中位数（230.3）**高于**出厂中位数（228.5），`novice` 档现场（55.6）**低于**
  出厂（61.9）。所以谁拿出厂分数去预测现场抽题、或者反过来，都会错。
- CI 里那一跑是 `SAMPLES: "12"`（`.github/workflows/ci.yml:43`），本页是 `SAMPLES=24`（`tools/balance.mjs:6`
  的注释把 24 这一跑指定为"README/DESIGN 引用的那张表"）。样本数不同，分位数就不同，同理不可互换。

想复现这两列，用本页最后一节的 A/B 两条探针命令；不要把 `balance` 的表读成"菜单里那 20 关的分数"。

## 四条承诺

1. **零猜测。** 每一关都由一条**不回溯**的铅笔路径从空盘推到完（`solve()`，`js/engine/skyscraper.js:590`）。
   写进盘里的每个数都是"这条线的每一种相容摆法都同意"的事实，所以它在**每一个解**里都成立。
   复现：`node tools/bake.mjs --check` → `铅笔推到底 20`。
2. **唯一解由第二套互不信任的穷举器逐格复核。** 判定唯一性不靠铅笔路径自己说：
   `js/engine/count.js:48` 的 `countSolutions()` 自带一份**重写过的**"能看见几栋"实现、自带一套回溯搜索、
   连哨兵常数都不与引擎共用（`ABSENT = -1` / `NOTHING = 0`，`js/engine/count.js:18-19`）；
   `js/engine/count.js:157` 的 `countNaive()` 是第三份意见，搜索途中**一个线索都不用**，
   只在拉丁方成形后把四条边的数读出来对。复现：`node tools/bake.mjs --check` → `唯一 ✓ 穷举同解 ✓ 朴素 ✓`（20/20），
   以及 `bash tools/verify.sh` 的 `unique` 场景（每形 50 条，含 `MANY` / `NONE` 两个反向对照）。
   **这一条从 `11881a5` 起换了位置**：复核不再只活在 `bake --check` 里，它接进了出题路径本身
   （`js/engine/generate.js:253`，候选盘在参与打分之前先过 `countSolutions`），
   `OVERBUDGET` / `MANY` / `NONE` / 与铅笔 `derived` 逐格不一致四类**全部拒绝**——没数完的盘进不了选择键，
   不存在"可能是唯一"的解释空间。预算按**节点**计价（`PROOF_BUDGET = 40,000,000`，`js/engine/generate.js:65`），
   所以这条复核在 node、浏览器与 `bake` 里逐次同价，墙钟进不了判定（见 DESIGN §8）。
3. **提示只给下一步可证事实。** 提示脚本是**线索**推出来的那条路径，不是玩家墨迹推出来的
   （`this.script = solve(puzzle.board).rows`，`js/ui/game.js:50`）；写下的每个数都点名它依据哪条边的哪个数。
   玩家写了与线索矛盾的数时，提示只说矛盾、**不扣提示次数、也绝不偷偷改掉你的数字**（`js/ui/game.js:199-205`）。
   复现：`bash tools/verify.sh` 的 `hint` 场景 —— 每形 198 条，本机 `totalHints: 472`、`charged: 16`、`spun: 25`。
4. **难度是量出来的。** `band` 是选盘目标而不是装饰，`balance` 两道人审：每档 ≥75% 的样本要落进自己的带、
   中位数必须在带内、五档中位数必须严格递增，且"上手线索要比初学少、高阶要比熟练少"（`tools/balance.mjs:209-221`）。
   复现：`SAMPLES=24 node tools/balance.mjs` → `== 结论 ：门禁全过（29.9s） ==`（01:06 那一跑自报 27.2 s；
   这一条是脚本自己的计时，随负载变，本页只留读数不当结论）。

## 不承诺

- **不承诺"人一定推得动"。** 分数与深度量的是**这条推导脚本**的成本，不是主观体感；深度 3 也不等于简单。
- **不承诺规则集完备。** 铅笔规则只能证明"这堆墨已经死了"，不能证明"这堆墨还活着"
  （`deadEnd()` 的方向性写在 `js/engine/skyscraper.js:629-643`）。死局判定是可靠的，"没报死局"不是保证。
- **不承诺 6 阶的唯一解由朴素枚举独立证明。** 6 阶拉丁方有 812,851,200 个，出厂 6 关只钉住首行
  （1,128,960 个）作旁证；全局唯一那一票始终投在 `countSolutions()` 上（`tools/balance.mjs:145`）。
- **不承诺出题时延。** 本机 `SAMPLES=24` 跑出的 `ms p50 / ms p90` 是 初学 0/3、上手 2/5、熟练 4/9、
  高阶 4/20、大师 **45/256** —— 这是**这台机器这一次的读数**，随机器和负载变，不作为承诺。
  口径在 `11881a5` 变了：这一列现在**含**唯一性复核（复核就插在 `makePuzzle` 的候选盘进打分之前），
  上一轮同一列是 0/4、1/2、2/7、3/7、12/23。多出来的钱花在大师档：p50 12 → 45 ms、p90 23 → 256 ms。
  页内出题走的是同一个函数，所以手机上也同样要付这笔——而**没有任何一道闸断言过浏览器里单次出题的耗时**
  （`verify` 的 `seed` 场景只证明浏览器与 Node 在同一预算下抽出**逐格相同**的 7 张盘——含 `gen` 那一个
  "为落进带内采了几张盘"的计数也相同，见下——不计时）。
- **不承诺跨版本存档。** 存档键是 `skyscraper.save.v1`（`js/store.js:6`），清洗器只兜这一种形状；
  旧格式会被当成"没有存档"，不会迁移。
- **不承诺 7 阶以上。** 见上面 `7 阶 0/120`。

## 文档也有一道闸（`node tools/doctest.mjs`）

本页与 `DESIGN.md` 印出去的每一个现值都由 `tools/doctest.mjs` 当场重算再对：出厂 20 关从 `clue` 串重解、
再交给两个独立穷举器判一遍（**不读 `js/data/levels.js` 里记着的答案**——生成器自己记的数在剪线索之后就不作数了）；
每档 24 题按 `balance-<档>-<k>` 那批种子重造；规则开火普查、`>>>FIXTURE` 夹具表、端口与 `SAMPLES` 口径、
`file:NN` 引用与锚点表、阶梯表与中位链都在里面。它分 D1–D14 十四组、全跑 281 条断言（脚本尾部打
`rows: 281 fail: 0`，文件里 `EXPECT_ROWS` 钉的是 281），tools/verify.sh 里钉的 doctest 断言数是 281 ——
整段检查被删掉时条数对不上就红，不会留下一声"绿"。

`file:NN` 引用有两条腿。一条核**手抄的锚点表**（表的条数由 `DESIGN.md` 那张闸表那一格钉着，与本次解析到的条数对账）：逐条要求那个标识符真坐在被指的那一行上。
另一条把同一份文档当输入**现推锚点**——`path:NN` 旁边贴着写出来的那个反引号名字，必须出现在被指的那几行里，
**表里没抄的那些也照核**。本轮现推锚点 12 条（口径：一条锚点是"哪一行 + 哪个名字"，同一处在两份文档里各写一次只算一条），
其中手抄表没钉的 3 条：
`js/engine/skyscraper.js:148` 的 `Rules`、`js/main.js:969-970` 的 `window.App`、`js/library.js:143-148` 的 `dateSeedAt`。
这一格不是装饰：它上线这一轮就把旧文档里那句 `window.App` 的引用判了出来——那句赋值在 969 到 970 行，
旧文档指的却是同一个文件里更早的 922，而 922 在一份 1089 行的文件里当然"不越界"，只有范围检查的那条腿一路绿。
**这条腿没覆盖什么**也写在这：文档里还有大量裸 `path:NN`，句子里没有贴着写的标识符，现推腿拿不到锚点，
它们仍只过范围检查；要给它们补，得先把那几句话改写成人能读的样子（贴上去一个标识符，闸数到的那个数就涨 1，文档这两句得跟着改，只改一边就红）。

墙钟那一类（`engine-test` 9.4 s、`balance` 29.9 s、`verify` 34.8 s、`45 / 256 ms`）**这道闸一条都不重测**，
也不新写读数：它只在文档把计时当成现值来断言时红。

台账 `node tools/sabotage.mjs` 是这道闸的反证：全绿只说明这一轮没东西坏，没说它会不会红。每一把刀把一类谎
写回树里（改 `TIERS` 的带、改出厂关卡的线索串、改 README 那句引擎断言条数、改 `verify.sh` 的 want 端口、
往 `js/` 里塞一条反向 import、改 `scenarios.js` 的夹具字段、把一句引用的起始行往后挪两行），要求 doctest `rc ≠ 0` **且**点名它杀的那条断言，
FAIL 行原文进日志；恢复用的是下刀之前读进内存的那份字节（本工作区禁用 `git checkout` / `restore` / `reset`，
它也不需要），跑之前工作树必须干净。实测退码由脚本自己读回来盖进台账表。

## 文档纪律

- 文档是**承诺**，不是事实：`js/`、`tools/` 的代码 > 本文档。
- 本文里的每个数字要么来自本页最后一节能跑出来的命令，要么明写"未验证"。
- 本文引用代码用的是 `file:line`，每条都在最后一次编辑后按标识符复验过；行号漂了请以那一行的标识符为准。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`31`）与这一次跑的断言条数（`49`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`31`、断言仍然 `49`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 里也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
